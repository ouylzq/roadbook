# 场景：GitHub 仓库主流程（公网只读）

## 什么时候跑

用户说「拿个公网大站跑一遍」「换个著名产品演示一下」「GitHub 主流程还通不通」，
或者要给没接触过这套东西的人看一个不用本地起服务、不用内网就能跑的场景。

它和 `todo-*`（单文件 demo）、`gitea-issue-flow`（本地起的开源实例）都不同：被测的是
**公网上一个真实存在、天天在变的产品**，没有本地后端，也没有可造的数据。

## 目标

打开一个知名开源仓库，三屏都真的加载出对应的内容：仓库页能读到仓库名和自述文件、
工单列表能列出带编号的工单、点进去的那条工单详情跟列表里的是同一条。

## 环境

公网直连，不需要起任何本地服务。入口是 `https://github.com/facebook/react`——
选它是因为它是家喻户晓的开源仓库、匿名可访问、自述文件长期稳定、工单列表一直在动。

（GitHub 会把这个地址 301 到 `react/react`，落地的仓库名以跳转后的为准。）

## 固定参数

- 仓库入口：`https://github.com/facebook/react`
- 工单列表：`https://github.com/facebook/react/issues`
- 要核对的自述文件原文：`React is a JavaScript library for building user interfaces.`
  这句是 React 自述文件的第一句，长时间没变过；改这里要同步改 `expect.yaml`。
- 挑哪条工单：**列表里的第一条**，别自己挑。它的编号和标题要写进下面的 context。

## 留给裁判的事实

`runs/<本次>/context.yaml`：

```yaml
issue_number: <你点开的那条工单的编号，纯数字，不带 #>
issue_title: <那条工单的标题原文>
issue_url: <那条工单的完整地址>
```

仓库地址和工单列表地址都是写死的，验收路线里直接写地址。**要开变量的只有「点开哪一条」**——
那是跑的时候才定下来的。

## 清理

不需要：全程只读，不登录、不建任何东西。GitHub 上没有任何你留下的状态。

## 红线

- **只读。** 不要登录、不要发工单、不要评论、不要点 Star / Fork / Watch，不要下载任何东西。
- 遇到登录墙、人机校验、「访问过于频繁」这类拦截页，一律判 `blocked`，不要试图绕过。
- 不要给这个仓库点任何会改状态的东西——它是别人的真仓库，不是我们的测试环境。
