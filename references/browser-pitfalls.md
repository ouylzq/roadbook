# 浏览器工具的坑

下面每一条都是驱动真实单页应用时实测出来的，不是推测，也不是从工具文档里能看出来的。
如果你在做类似的 UI agent，这是最值得先读的一份。

## 1. 钉住视口会让打字失效

两种行为，你不能两头都要：

| 设置 | 像素坐标 | 打字 |
|---|---|---|
| `resize_window` 钉成固定尺寸 | 准——截图帧和视口一致 | **`type` 静默失效**：光标在、placeholder 消失了，但字进不去 |
| `resize_window preset=desktop`（不钉） | 截图被缩放，每次点击前必须用新截图重新算坐标 | 正常 |

**规则：任何需要打字的步骤都必须在不钉视口的状态下跑。** 只有纯点击的步骤才可以钉。
这条排查花了四个错误假设才定位——它的表现看着像焦点 bug，完全不像视口 bug。

不钉视口的推论：**每次点击前立刻重新截图，只用那张图的坐标。**
绝不跨截图复用坐标。pane 可能在两次调用之间被改变尺寸，
帧会跟着重新缩放，你手里的坐标就全部静默失效了。

## 2. 刚滚动完拍的截图是动画中间帧

平滑滚动有动画。你拿到的那一帧是页面运动中的样子；
等你按那个坐标点下去，页面已经停在几百像素之外，点击落到了别的控件上。

**滚动后等 1-2 秒再截图。** 有一次因此把便宜的选项点成了贵的，
而且因为"选项看起来自己变了"，差点当成产品 bug 上报。

## 3. pane 会被隐藏，隐藏时页面根本不渲染

用户切走浏览器 pane 时，页面停止渲染：

- `computer` 的滚动 / hover / 拖拽 / 截图 **直接超时**
- 隐藏期间加载的页面**没有排版**——`read_page` 报 0×0 视口，按 ref 点击落不到任何地方

还能用什么、该怎么办：

1. 隐藏时**按 ref 点击、`find`、`read_page`、`get_page_text` 仍然可用**。
   靠这几样能走完一整段流程——单选框、步进器、提交按钮都能按 ref 点，
   结果用页面文本验。这是硬边界允许的 DOM 退守，把原因写进 run 报告即可。
2. **隐藏期间不要刷新。** 必须刷新时先对同一 URL 调 `preview_start`——
   它会把 pane 拉回来并**新开一个 tab**。关掉旧 tab、在新 tab 上继续，
   tab id 变了，后续每个调用都要带新的。
3. 最省事的办法是让人把 pane 留在前台。

## 4. 渲染落后于请求：不可逆按钮绝不点第二次

点完确认按钮，截图可能还显示着原样的弹层，按钮看着像禁用。
其实点击已经被接受了，只是渲染没跟上。**第二次点击可能意味着第二次扣费。**
等 5–10 秒、重新读文本、或者查读接口——不要补点。

同一个问题的镜像：弹层可能在**被绘制之前几秒**就已经在 DOM 里了（`find` 能找到它的内容）。
所以提交之前，确认金额要从**文本**里读，不要从截图上看。

## 5. 乐观 UI：屏幕不等于后端

一个步进器从 4 改到 2。卡片显示 2。概览面板——另一个组件——也显示 2。
后端仍然是 4，真实数字只在最后的确认弹层里出现。
同一天另一个 bug：保存弹层报告成功，而存储的值根本没变。

**先刷新，再读。** 这两个 bug 刷新之后立刻现形。
另外，改完值要留间隔：有些控件重算期间会显示占位符，这个窗口里的第二次点击会被丢掉。

## 6. 没有文件上传工具，得自己注入 File

agent 的浏览器工具里没有文件选择器。
点「+」或「添加附件」只会唤起操作系统的对话框，沙箱既看不到也驱动不了它——
页面毫无变化，看起来就像按钮坏了。

可行的做法是用脚本：在页面里构造 `File`（或 `DataTransfer`）并派发给
`input[type=file]`，然后读页面文本确认附件卡渲染出来了。
这是全套流程里**唯一一处脚本操作页面属于必需而非退守**的地方，
所以用到的地方要明确说明。

留神后续影响：附件卡通常异步渲染并把布局顶下去，你原本要点的东西已经移位了。
卡片出现后要重新截图——有一次因为这个，连续三次点击落到了场景推荐卡上，
把输入框内容替换成了模板。

## 7. 文本才是证据通道

`get_page_text` 默认取 `<main>`。固定 header 里的值——余额、计数器、账号胶囊——
经常也会被带出来；没带出来时用 `read_page` 读 header 区域，并注明原因。
截图用来确认页面加载状态、用来定位。它永远不是证据，任何判决都不建立在截图上。

## 8. 可访问树不显示勾选状态

`read_page` 里 checkbox 只有名字（`checkbox "切换 xxx"`），**勾没勾看不出来**，`get_page_text`
更不会有。所以"这条任务已完成"这种状态不能拿列表页当证据——要么去一个把状态写成文字的页面
（统计页的「已完成 N」、header 的「未完成 N」），要么按裁判协议「表单控件的值怎么取证」用
只读脚本读 `checked`，并在 `how` 里说明为什么文本层读不到。写 `expect.yaml` 时就该避开这个坑：
把状态类的 check 指向有文字的那一屏。
