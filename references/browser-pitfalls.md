# 驱动真实单页应用的坑

下面每一条都是驱动真实单页应用时实测出来的，不是推测，也不是从工具文档里能看出来的。
如果你在做类似的 UI agent，这是最值得先读的一份。

**这份只收跟运行时无关的坑**——换一套浏览器工具照样成立的那些。
某个工具自己的毛病（视口、pane、上传能力差异）在 `references/runtimes/<你的运行时>.md` 里，
开跑前连那份一起读。两层怎么分见 `references/runtime-contract.md`。

## 1. 刚滚动完看到的画面是动画中间帧

平滑滚动有动画。你看到的那一帧是页面运动中的样子；
等你按那个位置点下去，页面已经停在几百像素之外，点击落到了别的控件上。

**滚动后等 1-2 秒再看画面。** 有一次因此把便宜的选项点成了贵的，
而且因为"选项看起来自己变了"，差点当成产品 bug 上报。

## 2. 渲染落后于请求：不可逆按钮绝不点第二次

点完确认按钮，画面可能还显示着原样的弹层，按钮看着像禁用。
其实点击已经被接受了，只是渲染没跟上。**第二次点击可能意味着第二次扣费。**
等 5–10 秒、重新读文本、或者查读接口——不要补点。

同一个问题的镜像：弹层可能在**被绘制之前几秒**就已经在 DOM 里了（找元素能找到它的内容）。
所以提交之前，确认金额要从**文本**里读，不要从画面上看。

## 3. 乐观 UI：屏幕不等于后端

一个步进器从 4 改到 2。卡片显示 2。概览面板——另一个组件——也显示 2。
后端仍然是 4，真实数字只在最后的确认弹层里出现。
同一天另一个 bug：保存弹层报告成功，而存储的值根本没变。

**先刷新，再读。** 这两个 bug 刷新之后立刻现形。
另外，改完值要留间隔：有些控件重算期间会显示占位符，这个窗口里的第二次点击会被丢掉。

## 4. 文本才是证据通道

读页面文本默认只取主内容区。固定 header 里的值——余额、计数器、账号胶囊——经常也会被带出来；
没带出来时用读页面结构去取 header 区域，并注明原因。

画面用来确认页面加载状态、用来定位。**它永远不是证据，任何判决都不建立在画面上。**

## 5. 可访问树不显示勾选状态

可访问树里 checkbox 通常只有名字（`checkbox "切换 xxx"`），**勾没勾看不出来**，页面文本更不会有。

所以"这条任务已完成"这种状态不能拿列表页当证据——要么去一个把状态写成文字的页面
（统计页的「已完成 N」、header 的「未完成 N」），要么按裁判协议「表单控件的值怎么取证」
用只读脚本读 `checked`，并在 `how` 里说明为什么文本层读不到。
写 `expect.yaml` 时就该避开这个坑：把状态类的 check 指向有文字的那一屏。

## 6. 文件选择器是操作系统的，不是页面的

点「+」或「添加附件」唤起的是操作系统对话框。页面上什么都不会变，看起来就像按钮坏了。

**能不能驱动它、怎么驱动，取决于运行时**——有的运行时有真正的上传能力，
有的得靠脚本往 `input[type=file]` 里塞构造出来的 `File`。看你那份运行时文件。

不管用哪种，留神后续影响：附件卡通常异步渲染并把布局顶下去，你原本要点的东西已经移位了。
卡片出现后要重新看画面——有一次因为这个，连续三次点击落到了场景推荐卡上，
把输入框内容替换成了模板。
