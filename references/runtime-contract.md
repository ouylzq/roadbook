# 运行时契约

路书要驱动浏览器，但**路书本身不该知道浏览器是谁在驱动**。

同一份场景、路书、原子，可能跑在很不一样的地方：有人在自己电脑上盯着跑，
有人把它扔进容器里无人值守跑。这两处手里的工具不是同一套，名字也对不上。
如果资产里写死了工具名，换个地方跑就全废了——而资产（对界面的描述）恰恰是这套东西里最贵的部分。

所以分两层：

| 层 | 是什么 | 谁维护 | 换运行时要改吗 |
|---|---|---|---|
| **资产层** | `scenarios/*/`、`atoms/*.md` | 人和 agent | **不改**。只描述画面和意图，只说下面的能力名 |
| **运行时层** | `references/runtimes/<名字>.md` | skill 维护者 | 加一个运行时 = 加一个文件 |

**加一个新运行时的完整步骤：写一份 `references/runtimes/<名字>.md`，照下面的表把每项能力绑到具体工具上，
把它特有的坑写进去。资产层一个字都不用动，SKILL.md 也不用改。**

## 能力词表

资产层（原子、路书、场景）描述操作时**只许用左列这些词**，不许出现任何具体工具名。
右列由各运行时自己去绑。

| 能力 | 做什么 | 备注 |
|---|---|---|
| **看画面** | 截当前一屏 | 用来定位、确认加载状态。**永远不是判据** |
| **按坐标点** | 按像素点击 | 默认的驱动方式 |
| **读页面文本** | 取页面可见文字 | **唯一的证据通道**，默认取主内容区 |
| **读页面结构** | 取可访问树 / 元素清单，产出可点的引用 | 主内容区之外（弹层、header）要靠它 |
| **按引用点** | 用上一条拿到的引用点击 | 像素定不准时的退守手段 |
| **找元素** | 按文案或角色搜元素，产出引用 | |
| **打字** | 模拟真实键盘输入 | 受控组件只认这个 |
| **写表单值** | 直接给表单控件赋值，不走键盘 | 快，但可能绕过前端状态更新 |
| **打开网址** | 导航到 URL | 回读、重载都靠它 |
| **跑只读脚本** | 在页面里求值并取回结果 | 取表单控件 value 这类文本层读不到的证据 |
| **设视口** | 改变视口尺寸 | |
| **管标签页** | 列出 / 切换标签页 | |
| **提议原子** | 交出一条关于某个节点的教训 | 写不写、何时写由运行时定，见下面「记忆层」 |
| **给候选投票** | 对建议区里一条候选投确认 / 否决 | 只在按它试过之后 |

某个运行时**没有**某项能力时，它自己的文件里要写清楚：缺哪一项、替代做法是什么。
资产层不为此改写——遇到这种情况是运行时文件负责给出绕法。

## 记忆层

原子由 agent 产出，但**不该由跑批中的 agent 直接落盘**——理由和规则在 `atoms/README.md`「谁能写」。
运行时分两种，各自的文件里要写清自己是哪一种：

| 运行时 | 「提议原子」「给候选投票」绑到 | agent 能不能直接写 atoms/*.md |
|---|---|---|
| **有记忆层** | 两个工具。运行时收下候选、注入后续跑批的任务说明、数票、落盘、记账本 | **不能**——工具里就没有 |
| **没有记忆层** | 不绑工具；agent 自己编辑文件 | 能，但要自己守同一套规则：已有原子只追加、新原子直写、「它长什么样」不动、不删 |

两种运行时跑出来的 `atoms/` 应该长得一样，差别只在谁把关。

## 怎么知道自己在哪个运行时

开跑前看一眼手上**实际可用的工具**，对照 `references/runtimes/` 里各文件开头的「怎么认出是我」，
认出来之后**先读那一份**，再开始跑。认不出来就停下说明情况，别拿一套工具去猜另一套的用法。

现有的运行时：

| 文件 | 什么时候是它 |
|---|---|
| `runtimes/claude-pane.md` | 在 Claude Code 桌面版里交互式跑，有内置浏览器 pane |
| `runtimes/playwright-mcp.md` | 无头容器 / CI 里跑，接的是 Playwright MCP 服务器 |

## 写资产时的纪律

- 原子的「已知会失败的方式」写**现象 → 机制 → 对策**，对策用能力名，不用工具名。
  例：不要写「用 `form_input` 塞」，写「直接写表单值」。
- 一个坑如果只在某一个运行时上出现（工具本身的毛病），它**不属于原子**，属于那个运行时的文件。
  判断标准很简单：换一套工具还成立吗？成立就留在原子里，不成立就搬走。
- `tests/lint_atoms.py` 会机械检查这条：原子里出现已知工具名会报错。
