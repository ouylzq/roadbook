# 探索模式的规矩

## 什么时候允许探索

只有两种情况：该场景还没有 `playbook.md`；或者回放中途锚点失配。
登录永远不算探索目标——它有自己的配方。

## 探索时

- `intent.md` 只给你目标、固定参数和红线，**不给步骤**。步骤是你勘出来写进路书的。
- **先 `python3 scripts/atoms.py` 扫一眼索引**，像和这条流程相关的原子打开读，再动手。
  索引为空就从零探，那是正常的——首跑本来就没有记忆。
- 手段不限：截图、`read_page`、`find`、读被测应用的源码（只读）找 testid 都行。
- 优先找**语义锚点**，按稳定性排序：
  `data-testid` > `aria-label` / role + 文案 > 全页唯一的可见文案 >
  相对位置描述（"标题栏右侧第二个按钮"）。
- **坐标永远不进路书。** 横幅高度变一次，所有坐标就全废了。

## 回写路书是交付物，不是附加项

`playbook.md` 的格式：

```markdown
# <场景名> 路书
> 最后勘路：<日期>，对应环境 <环境名>

## 步骤
1. 【参考】outline-edit
   【目的】进入编辑态
   【锚点】标题栏按钮 data-testid=outline-edit-save-toggle（文案「编辑」）
   【动作】点击
   【到位标志】同一按钮的文案变成「保存」
2. ...
```

每步五个字段：**参考 / 目的 / 锚点 / 动作 / 到位标志**。
「到位标志」是回放模式判断"这步成了没有"的依据——写不出到位标志，
说明这一步你还没勘明白，回去重看。
「参考」指向 `atoms/` 里的一个原子，或写 `—`（没有对应原子，或胶水步）。
它的语义只有一句：**这一步失配时先读它，再自由探索。** 首跑写出来的路书多半全是 `—`，
沉淀了原子之后再回填。`tests/lint_playbook.py` 会校验名字真的存在。

## 失配了先翻参考，再自由探索

回放到某步锚点找不到、或到位标志没到：

1. 有 `【参考】` → 打开那个原子，按它的「变体」逐个试，按它的「已知会失败的方式」
   排查自己是不是踩了老坑。没有 `【参考】` → `python3 scripts/atoms.py` 查索引里有没有讲这个节点的。
2. 都没有，再按上面"探索时"的办法自由找路。
3. 勘通之后按下面的沉淀规则写回去。

原子是给"刚在这一步失败了的 agent"写的手册，读者就是此刻的你。

## 更新纪律

- **只改失配的那几步**，别整份重写。git diff 就是 UI 变更记录，
  评审的人应该能从 diff 里直接读出"保存按钮从标题栏挪到了底部"。
- 更新文件头的"最后勘路"日期。
- 失配的**原因**（改版 / 元素改名 / 流程变了）写进本次 run 的报告，不写进路书。
- 交棒给裁判的那些步——写 `context.yaml`、起裁判——和别的步一样放在路书末尾，
  也要有自己的到位标志（`judgment.yaml` 出现了；judge.py 给出了退出码），
  `【参考】` 写 `—`。

## 沉淀：跑完把学到的东西写回原子

每次 run 结束、写报告之前做一遍（SKILL.md 第 8 步）。只有三种事值得变成原子：
踩了坑然后找到了通路；界面和预期不一致而最后弄清了机制；人纠正了你的操作。

- 按原子里已有的**变体**勘通的 → **只改路书**那一步。
- 原子里**没有**、自己新勘出来的 → **路书和原子同时写**：路书改那一步并回填 `【参考】`，
  原子的「变体」或「已知会失败的方式」加一条，写成「现象 → 机制 → 对策」。
  **不写日期、不写"本轮/今天/我"**——规则要脱离故事也成立，什么时候发生的交给 git log。
- 新建前先合：`python3 scripts/atoms.py` 看同一节点有没有原子，有就追加，不开近似重复的新文件。
- 看到了但没走的分支 → 建存根原子（只要索引行和「它长什么样」）。
- 顺利走过、什么都没学到的步 → 不写。路书记路径，原子记路径之外的知识。
- 工具层的发现（换个产品也会撞的）往 `references/browser-pitfalls.md` 写，原子只指过去。
- 写完跑 `scripts/atoms_status.py` 刷账本，`tests/lint_atoms.py` 看写法警告。
- 原子改了要重跑谁：`grep -l "【参考】<原子名>" scenarios/*/playbook.md`。
