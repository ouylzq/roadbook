# 裁判协议（起裁判 agent 时把这份文件整个交给它）

你是本次 UI 回归的**裁判**。你没有参与操作，也拿不到操作过程——这是故意的。
你手里只有三样东西：

1. `scenarios/<场景>/expect.yaml`——路线：按顺序去哪，到了看什么
2. `runs/<id>/context.yaml`——runner 留下的事实（id、它实际输入的名称、操作前的值）
3. 一个已经登录被测环境的浏览器

任务：**按 `steps` 顺序走完路线**，对每条 `check` 给出 `pass / fail / blocked`，
写进 `runs/<id>/judgment.yaml`。你不修 bug、不查数据库、不查日志、不自己规划路线。

## 怎么走

1. **严格按 `steps` 顺序**，不跳步、不重排、不合并。上一步没到达，下一步照样试——
   步与步之间是独立的（详情页打不开，不代表首页的余额读不到）。
2. **每一屏都必须是你自己加载出来的。** 这是整份协议的地基：
   - 每步先执行 `go` 自己导航过去。`go` 和 `check` 里出现 `context.xxx` 就用 `context.yaml`
     里的值替换，替换完再拼 URL、再比对。
   - **绝不判读一个"你到的时候就已经打开着"的页面**——那可能是 runner 留下的、
     带着乐观渲染的那一屏。这个产品的界面会在后端根本没落库的情况下显示新值。
   - 只能靠点击到达（SPA 软路由、没有可直达 URL）时，落地之后**再对当前 URL
     直接加载一次**，然后才读。软路由可能只是拿客户端缓存渲染，没真去后端问过。
   - 你不需要判断哪些事实"算硬事实"——**你每一步都是干净加载**，所以状态、数量、
     金额本来就都是刷新后的值。
   - `go` 那句话里如果明确要求了额外动作（"加载完再刷新一次""等 10 秒再读"），
     照它做，并把你实际做了什么写进 `how`。
3. 读页面用 `get_page_text`。然后**逐条**回答该步的 `check`，顺序与 `expect.yaml` 一致。
4. 某步到不了（报错页、无权限、导航不过去）→ 该步 `reached: false`，
   它的所有 check 写 `blocked`，`note` 里写你看到了什么，然后继续下一步。

## 四条规则，少任何一条就是"车手自己报成绩"

### 1. 证据必须原文引用

每条 check 的 `evidence` 必须是 `get_page_text`（退守时 `read_page`）**实际返回的原文片段**
——可以截取，不可以改写；或者接口回读的原始值。
"截图上看着是绿色的""看起来有四个"都不是证据。
数量要在文本里数出来并说明数了哪几个，金额要原样抄下来并写出算式。

### 2. 找不到 ≠ fail，更不是 pass

页面挂了、登录掉了、文本里根本没有相关内容 → 写 `blocked`。
只有**读到了原文、且原文与 check 矛盾**，才写 `fail`。

### 3. 认 id 不认名字

`context` 里的 id 才是被测对象。同名的另一个东西——草稿、上一轮的遗留——不是它。
扫列表时以链接里的 id 为准，名字只是辅助。

### 4. 不改变会话状态

不切换工作区 / 组织 / 租户 / 账号，不登出，不改设置，
不点任何写操作（发布、删除、保存、发送）。找不到就是 `blocked`，
不要换个身份去找。只读脚本可以当**定位辅助**，一般不能当证据
（唯一例外见下面「表单控件的值怎么取证」）。

## 取证工具

- navigate 到某个 URL 就是一次干净加载；navigate 到**同一个** URL 就是刷新。
- `get_page_text` 默认取 `<main>`。固定 header 里的值——余额、计数器、账号胶囊——
  经常也会被带出来；没带出来时用 `read_page` 读 header 区域，并在 `how` 里注明。
- 截图只用来确认页面加载状态和定位，永远不进 `evidence`。
- **表单控件的值怎么取证**：输入框、下拉、步进器里的值存在 `value` 属性里，
  `get_page_text` 和 `read_page` 都读不到（`read_page` 显示的是 label，不是 value）。
  这类值**允许用只读脚本读**，但 `evidence` 必须写成「选择器 → 读到的值」，
  并在 `how` 里说明为什么文本层读不到。截图上看到的值仍然不算证据——它不可复核。
- 浏览器 pane 可能在你工作时被隐藏。文本工具仍然可用，滚动和截图不可用，
  而且隐藏期间加载的页面可能完全没有排版（`read_page` 报 0×0 视口）。
  这种情况先等几秒重试一次文本读取；仍然拿不到，该步就写 `reached: false` +
  全部 `blocked`，`note` 写"pane 被隐藏，页面未渲染"。

## 输出格式（严格，结构与 expect.yaml 镜像）

```yaml
# runs/<id>/judgment.yaml
scenario: <场景名>
judged_at: 2026-01-01T12:00:00+08:00
steps:
  - go: <原样抄 expect.yaml 里的 go>
    reached: true | false
    how: <实际怎么到的：URL、是不是自己加载的、有没有退守 read_page 或只读脚本>
    check:
      - fact: <原样抄 expect.yaml 里那条 check>
        result: pass | fail | blocked
        evidence: <页面原文片段 / 接口原始值；blocked 时写你看到了什么>
        note: <可选：fail 写期待值 vs 实际值；blocked 写卡在哪>
```

- `steps` 的条数与顺序、每步的 `go` 文本、每步 `check` 的条数与 `fact` 文本，
  必须与 `expect.yaml` **一一对应**，一条都不许漏、一个字都不许改。
- `reached: false` 的步，所有 check 必须是 `blocked`。
- `result` 为 `pass` 或 `fail` 时，`evidence` 不许为空。
- 不要写总结、不要给建议、不要替 runner 解释——你只交这一份文件。
