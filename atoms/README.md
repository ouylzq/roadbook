# 原子（atoms）：agent 对被测产品的操作记忆

一个原子 = 被测产品主流程上**一个节点**的操作知识：它长什么样、有哪些入口、
会以什么方式失败、看到过什么分支。**全部由 agent 在跑的过程中沉淀，人不预先写。**

首跑时这个目录是空的，这很正常。跑一次长一点；不确定的时候回头查。

> 设计参考了 Hermes Agent 的 skills / memory 机制：agent 自己从经验里长 skill、
> "lessons, not logs" 的内容标准、只警告不拦的 linter、和内容分离的使用遥测、
> active → stale → archived 的生命周期。下面每条规矩后面都能找到那边的对应物。

## 什么时候记

三个触发，缺一个都不记：

1. **踩了坑，然后找到了通路。** 点了没反应、点错了地方、状态没落库——最后搞明白了为什么、怎么绕。
2. **界面和预期不一致，最后弄清了机制。** 不是"看起来怪"，是知道了它为什么那样。
3. **人纠正了你的操作。** "不是那个按钮""那个值要刷新后再读"——纠正本身就是知识。

**不记**：顺利走过、没学到东西的步。路书已经记了路径，原子记路径之外的知识。
每步都写原子，索引就没法扫了。

## 怎么写：教训，不是日志

一条"已知会失败的方式" = **现象 → 机制（一句） → 对策**，挂在受影响的节点上，**只说一次**。

- **不写日期，不写故事。** "2026-09-08 我刚 navigate 完立刻点了 ref，结果报错"是日志；
  "导航之后 ref 全部过期——它绑定的是旧 DOM 节点；重新 find 再点"是教训。
  规则必须脱离故事也成立。什么时候发生的交给 git log；验到什么程度交给 STATUS.md。
- **不复述已经加载的东西。** SKILL.md 和 `references/browser-pitfalls.md` 每次都在上下文里，
  原子只**指**过去（"工具层坑，见 pitfalls §3"），不重抄。
- **短。** 一个原子 60 行以内。超过说明要么在写故事，要么这个节点该拆成两个。
- **开头的 frontmatter 就是索引。** `name` 是文件名，`description` 是一句完整的话（25～90 字）：
  哪个应用的哪个节点、长什么样、什么时候来查它——回忆时靠 `scripts/atoms.py` 列，
  只读这一行就该能决定要不要打开它。

## 先合再建

新建之前先 `python3 scripts/atoms.py`，再 `grep -l "<锚点文案>" atoms/*.md`。
同一个页面、同一组控件已经有原子 → **追加**到它的「变体」或「已知会失败的方式」，
不要开一个近似重复的新文件。

## 三个动作

### 查（回忆）—— 渐进披露

第一层 `python3 scripts/atoms.py`（一行一个，只有节点名；原子多时用 `--grep <文案>` 先筛），第二层 `python3 scripts/atoms.py <候选>` 只看它长什么样，第三层才打开整个文件。三个时机：

1. **探索开始前**（没有路书）。索引为空就跳过。
2. **操作中遇到不确定**：不知道该点哪、点了没反应或反应不对、没见过的弹层或状态、
   改了值不确定落没落库、到位标志到不了。
3. **回放失配**：先读这一步 `【参考】` 指的原子；没有 `【参考】` 就查索引。

回放顺利时不打开任何原子。

### 记（沉淀）—— 每次 run 结束、写报告前

- 探索过程中**随手**把怪事记进 `runs/<本次>/runner-notes.md`，别等最后凭记忆整理。
  这是给自己的提醒：每勘通一步，回头看一眼有没有值得记的。
- 结束时按上面三个触发筛一遍 runner-notes，命中的按"先合再建"落成原子，
  回填路书对应步的 `【参考】`，跑 `scripts/atoms_status.py`。
- 什么都没命中就在报告里写"无新知识"。

### 账（状态）—— 脚本推导，人不改

`scripts/atoms_status.py` 从 `runs/*/verdict.txt` 推导：

| 状态 | 含义 |
|---|---|
| 已验证 | 某个 PASS run 的路书 `【参考】` 了它，且最近一次在 30 天内 |
| 陈旧 | 上次被 PASS run 经过是 30～90 天前——界面可能已经变了，回放到它时多留意 |
| 归档候选 | 超过 90 天没被任何 PASS run 经过。**只归档不删**：挪进 `atoms/.archive/`，要用再挪回来 |
| 已引用，未验证 | 有路书引用，但没有 PASS run 经过 |
| 待勘 | 没有任何路书引用——存根原子（看到了没走的分支）就是这个状态 |

状态和内容分开：原子文件里不写状态，账本从 run 算出来。
这是把「PASS 只能由执行产生」从场景层推到原子层。

## 审批门就是 git diff

原子由 agent 写，但**落地要经人**：改动停在工作区，人看 diff 再提交。
diff 里读到"某个节点新增一条失败方式"，就是在审这条教训站不站得住。不需要别的审批机制。

## 边界

| 东西 | 住哪 | 加载时机 |
|---|---|---|
| 流程（按什么顺序做什么） | `playbook.md` | 回放时整份读 |
| 节点知识（这个控件怎么回事） | `atoms/` | 不确定时按需读 |
| 工具层的坑（换个产品照撞） | `references/browser-pitfalls.md` | 一直在 |
| 验什么 | `expect.yaml` | 裁判读 |

原子**不写流程**——不要在原子里写"第一步…第二步…"，那是路书的活。
原子**不写验证**——不写"断言"，验证只在 `expect.yaml`。
只为 runner 经过或注意到的节点建原子；裁判按 `expect.yaml` 的 `go` 走，不需要记忆。

## 文件格式

```markdown
---
name: <节点名>                                 ← 等于文件名
description: <哪个应用的哪个节点、长什么样、什么时候来查它>   ← 一句完整的话，25～90 字
---

# <节点名>

## 它长什么样
锚点在哪、正常路径是什么。失败者先用这段确认自己站在对的地方。

## 变体
别的入口、别的文案、改版后见过的形态。按"先试这个"排。

## 已知会失败的方式
- 现象 → 机制 → 对策
- …

## 出处
哪些路书引用了它。
```

存根原子只要索引行和「它长什么样」（写"看到了，未走过"）。
`tests/lint_atoms.py` 检查这些：格式错报错，写成日志、太长、索引行过长只警告不拦。

## 命名

`references/` 是这个 skill 自己的规矩；`atoms/` 是被测产品的记忆。
两个都叫"参考"会绕晕人，所以文件夹保留 `atoms`，"参考"只用来称呼路书里那个字段。
